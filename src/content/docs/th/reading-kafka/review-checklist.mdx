## Client & versions

- โค้ด import `kafkajs` หรือ `@confluentinc/kafka-javascript` — และคนรีวิวรู้ว่าเป็นตัวไหนก่อนจะตัดสิน default ไหนเลยหรือไม่? ดู **[AI Bug Catalog](/kafka/th/reading-kafka/ai-bug-catalog/)** รายการ 3
- config object ของ KafkaJS พก key เฉพาะ Java client (`group.protocol=consumer`, KIP-848) ที่ถูกทิ้งเงียบ ๆ แทนที่จะถูกปฏิเสธหรือไม่? ดูรายการ 2
- script shell ไหนส่ง `--zookeeper` ให้ tool `kafka-*.sh` หรือไม่? ถูกถอดออกเต็ม ๆ ตั้งแต่ Kafka 4.0 ดูรายการ 1
- comment สมมติว่าทุก compression codec หรือ partition assigner แบบ "sticky" มีให้ในตัวบน KafkaJS ทั้งที่มันมีแค่ `gzip` และแค่ `RoundRobinAssigner` หรือไม่? ดูรายการ 3

## Producer

- `idempotent: true` ถูกตั้งชัดเจนบน producer ที่ write ของมันสำคัญ แทนที่จะทิ้งไว้ที่ default จริงของ KafkaJS คือ `false` หรือไม่? ดู **[AI Bug Catalog](/kafka/th/reading-kafka/ai-bug-catalog/)** รายการ 4 และ **[Idempotent Producer](/kafka/th/producers/idempotent-producer/)**
- comment อ้าง compression codec (`lz4`, `snappy`, `zstd`) ที่ KafkaJS ไม่มี implementation จริงให้หรือไม่? ดูรายการ 5
- producer ที่สร้างด้วย `transactionalId` เคยเรียก `.send()` ตรง ๆ แทนการห่อทุก write ด้วย `.transaction()` หรือไม่? ดูรายการ 6

## Consumer loop & commits

- มีอะไรที่ช้า — HTTP call, DB write ที่ไม่มีขอบเขต — รันอยู่ใน `eachMessage` โดยลืมว่า heartbeat ของ KafkaJS ยิงแค่หลัง handler return แล้วหรือไม่? ดู **[AI Bug Catalog](/kafka/th/reading-kafka/ai-bug-catalog/)** รายการ 7 พิสูจน์ด้วย eviction จริงแบบ `coordinator is not aware of this member` และ **[Consumer API](/kafka/th/consumers/consumer-api/)**
- การเรียก `commitOffsets` แบบ manual ส่ง offset ที่อ่านมาเมื่อกี้ แทนที่จะเป็น `offset + 1` หรือไม่? ดูรายการ 8 พิสูจน์ด้วย duplicate จริงตอน restart
- พอ record ถูก route ไป dead-letter topic แล้ว โค้ด commit offset ของ message *ต้นฉบับ* หรือไม่? ดูรายการ 9 พิสูจน์ด้วย loop ประมวลผลซ้ำถาวรจริง

## Delivery & transactions

- loop consume-transform-produce commit consumer offset ด้วยการเรียก `commitOffsets` *แยก* แทน `txn.sendOffsets()` ภายใน transaction เดียวกันหรือไม่? ดู **[AI Bug Catalog](/kafka/th/reading-kafka/ai-bug-catalog/)** รายการ 10 พิสูจน์ด้วย duplicate จริงหลัง crash และ **[Exactly-Once Processing](/kafka/th/delivery-and-transactions/exactly-once-processing/)**
- `readUncommitted` เคยถูกสลับเป็น `true` เพื่อ "แก้" record ที่จริง ๆ ถูก abort ไปตั้งใจหรือไม่? ดูรายการ 11
- logic retry/abort เช็ค `error.retriable` ก่อนตัดสินใจ retry ไหม หรือ retry error ที่ fenced และ fatal ไปตลอดกาล? ดูรายการ 12 พิสูจน์ด้วย fencing error จริงที่ `retriable: false`

## Topic & broker config

- `replication-factor` ของ topic รองรับ `min.insync.replicas` ที่มันตั้งจริงหรือไม่ — หรือ combination นี้ถูกรับเงียบ ๆ ตาม KIP-579? ดู **[AI Bug Catalog](/kafka/th/reading-kafka/ai-bug-catalog/)** รายการ 13 และ **[Acks and Durability](/kafka/th/producers/acks-and-durability/)**
- การเพิ่ม partition ให้ topic ที่ใช้ key อยู่แล้วมีแผนสำหรับ reader ที่พึ่ง per-key ordering หรือไม่ — และ client producer/consumer ที่รันอยู่นานทุกตัวได้ refresh metadata หรือไม่? ดูรายการ 14
- `auto.create.topics.enable` (หรือ static broker config อื่น) ถูกสมมติว่ามีผลจากการเรียก `kafka-configs.sh --alter` แบบสด ๆ หรือไม่? ดูรายการ 15 พิสูจน์ด้วย `InvalidRequestException` จริง

## Ops & security

- script หรือ runbook ไหนอ้าง CLI tool ที่ไม่มีอยู่จริง (`kafka-metadata.sh`) หรือไม่? ดู **[AI Bug Catalog](/kafka/th/reading-kafka/ai-bug-catalog/)** รายการ 16 พิสูจน์ด้วย error "no such file" จริง
- command ไหนส่ง flag ที่ไม่มีอยู่จริงบน tool จริง (`--run-all`) หรือไม่? ดูรายการ 17 พิสูจน์ด้วย `UnrecognizedOptionException` จริง
- runbook เรียก `kafka-acls.sh` บน cluster ที่ไม่เคยตั้ง `authorizer.class.name` หรือไม่? ดูรายการ 18 พิสูจน์ด้วย `SecurityDisabledException` จริง และ **[Security and Production](/kafka/th/operations-and-production/security-and-production/)**

## Connect / Streams / Schema

- Connect ถูก deploy แบบ `standalone` สำหรับอะไรที่ต้องการ fault tolerance แทน `connect-distributed.sh` หรือไม่? ดู **[AI Bug Catalog](/kafka/th/reading-kafka/ai-bug-catalog/)** รายการ 19
- connector config อ้าง class ที่อยู่บน `plugin.path` จริง ไม่ใช่แค่มีอยู่บน disk ที่ไหนสักแห่งหรือไม่? ดูรายการ 19 พิสูจน์ด้วย `BadRequestException` รูปร่าง `ClassNotFoundException` จริงทั้งที่ jar มีอยู่
- `errors.deadletterqueue.topic.name` ถูกตั้งพร้อมกับ `errors.tolerance=all` (default จริง: `none`) — และตั้งบน connector แบบ **sink** เท่านั้นหรือไม่? ดูรายการ 20 พิสูจน์สด ๆ กับ `/config/validate` ของ worker ที่รันจริง
- โค้ดสมมติว่า KafkaJS consumer เข้าร่วม **share group** (KIP-932) ได้เลยหรือไม่? ดูรายการ 21 พิสูจน์ด้วย grep type definition ของ client เองที่ไม่เจอเลย และ **[Choosing a Processing Layer](/kafka/th/streams-connect-schema/choosing-a-processing-layer/)**

## Tooling

- `tsc --noEmit` ถูกรันบนทุก TypeScript snippet ก่อนเชื่อว่ามัน compile ผ่าน โดยรู้ว่ามันตรวจแค่ type ไม่เคยตรวจ durability, ordering, หรือ commit semantics เลยหรือไม่? ดู **[Verification Tools](/kafka/th/reading-kafka/verification-tools/)**
- `kafka-configs.sh --describe --all` ถูกรันกับ broker จริงก่อนเชื่อว่า config key มีอยู่จริงและ alter แบบ dynamic ได้ แทนที่จะสมมติจาก tutorial หรือไม่? ดู **[Verification Tools](/kafka/th/reading-kafka/verification-tools/)**
- CI รัน harness ของคอร์สนี้เอง (`npm run verify`, `--run`, `--cli`, `--props`) กับทุก fence ไม่ใช่แค่คนสไลด์ตาดูหรือไม่? ดู **[Verification Tools](/kafka/th/reading-kafka/verification-tools/)**
